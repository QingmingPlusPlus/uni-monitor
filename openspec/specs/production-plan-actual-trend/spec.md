# 生产性推移表规范

## Purpose

定义部门维度和工序维度的生产性推移表装配方式、六行指标、聚合公式、周期截止、图表语义与固定 mock 边界，确保未来替换真实接口时不改变当前业务口径。

## Requirements

### Requirement: 部门和工序按所属工序展示卡片

系统 MUST 在部门维度和工序维度展示生产性推移表。部门维度 MUST 按 `departmentProcessMap` 的顺序为每个所属工序生成一张卡片；工序维度 MUST 只生成当前工序的一张卡片。生产性卡片 MUST 位于真实生产计划实绩推移表之后；真实生产计划实绩推移表 MUST 位于入库卡之后，入库卡隐藏时紧接出勤率推移表。

#### Scenario: 制造4课展示两张卡片

- **WHEN** 用户进入制造4课部门维度
- **THEN** 系统 MUST 依次展示“加硫2 生产性推移表”和“后处理2 生产性推移表”
- **AND** 两张卡片 MUST 分别使用加硫和后处理口径

#### Scenario: 工序维度只展示当前工序

- **WHEN** 用户进入任一工序维度
- **THEN** 系统 MUST 只生成一张生产性推移表
- **AND** 卡片标题和数据口径 MUST 对应该工序

### Requirement: 卡片固定展示六行指标

系统 MUST 按工序族展示两行数量、两行 MH 和两行个数生产性。前处理数量行 MUST 为“计划粘接数、实绩粘接数”，加硫 MUST 为“计划加硫数、实绩加硫数”，后处理 MUST 为“计划入库数（含待倒箱、端数等）、实绩入库数（含待倒箱、端数等）”。其余四行 MUST 为“计划MH、实绩MH、计划个数生产性、实绩个数生产性”。

#### Scenario: 后处理使用完整行名

- **WHEN** 系统生成后处理生产性卡片
- **THEN** 第一、二行 MUST 分别显示完整的计划和实绩入库数长行名
- **AND** 系统 MUST NOT 使用通用“生产数”替代该名称

### Requirement: 固定 mock 采用统一日班次输入

本期生产性推移表 MUST 整卡使用固定 mock，并在标题旁显示“（mock）”。系统 MUST 将七日计划/实绩数量序列循环到当前月；前处理、加硫和后处理数量系数 MUST 分别为 `1`、`4`、`2.5`。能力 MUST 为 `6800 × 数量系数`，提高基础数 MUST 为 `64`，七日直接出勤 MH MUST 为 `63.5 / 65.0 / 64.0 / 66.0 / 64.5 / 65.5 / 67.0`，各班次 MUST 按 `40% / 35% / 25%` 拆分。

#### Scenario: 卡片刷新不请求业务接口

- **WHEN** 用户在部门或工序维度刷新生产性推移表
- **THEN** 系统 MUST 重新生成当前维度的固定 mock 卡片
- **AND** 系统 MUST NOT 请求生产计划、生产实绩或工时接口
- **AND** `getPlan` 和 `getOutput` 的既有缓存能力 MUST 继续可供信息汇总使用

### Requirement: MH 与个数生产性按周期合计派生

系统 MUST 按 `计划MH = Σ(计划数 ÷ 能力 × 提高基础数)` 计算计划 MH，并按 `实绩MH = Σ直接出勤工时` 计算实绩 MH。系统 MUST 按 `计划数合计 ÷ 计划MH合计` 与 `实绩数合计 ÷ 实绩MH合计` 分别计算计划和实绩个数生产性，MUST NOT 平均每日生产性。分母为 `0`、缺失或非有限值时，表格 MUST 显示 `-`，图表 MUST 使用 `null`。

#### Scenario: 周生产性先合计再相除

- **WHEN** 一个周周期包含多个日班次输入
- **THEN** 周计划个数生产性 MUST 等于该周计划数总和除以该周计划 MH 总和
- **AND** 周实绩个数生产性 MUST 等于该周实绩数总和除以该周实绩 MH 总和

#### Scenario: 无效分母不生成零值

- **WHEN** 某周期的对应 MH 为零、缺失或非有限值
- **THEN** 表格 MUST 显示 `-`
- **AND** 对应图表折线点 MUST 为 `null`

### Requirement: 周期与班次截止沿用生产推移规则

紧凑态 MUST 展示当月、接口周分段和当前周工作日；展开态 MUST 展示当月、全部周和当前月全部日期。月和周计划 MUST 只累计至当前生产班次，当前生产日的日列计划 MUST 展示当天全部班次。实绩和直接出勤 MH MUST 只累计至当前生产班次，未来日期 MUST 为空。00:00-06:29 MUST 归属前一生产日晚班。

#### Scenario: 当日计划与周累计使用不同截止范围

- **WHEN** 当前生产日仍有后续班次
- **THEN** 当日日列计划 MUST 包含当天全部班次
- **AND** 所在周与月计划累计 MUST 排除当前班次之后的计划

#### Scenario: 紧凑态不展示周末日列

- **WHEN** 当前周包含周六和周日
- **THEN** 紧凑态当前周日列 MUST 只展示工作日
- **AND** 展开态 MUST 仍可展示当前月全部日期

### Requirement: 表格格式保证指标可读

系统 MUST 将数量显示为带千分位的整数，将 MH 和个数生产性显示为一位小数。首列 MUST 提供足以完整显示后处理行名的宽度，当前约束为 `320px–340px`。

#### Scenario: 数量与小数采用不同精度

- **WHEN** 一个周期同时包含数量、MH 和生产性
- **THEN** 数量 MUST 以整数和千分位显示
- **AND** MH 与生产性 MUST 各保留一位小数

### Requirement: 图表使用柱线双轴且不展示 MH

图表 MUST 排除月列和两条 MH 系列。计划数、实绩数 MUST 使用分组柱状图并绑定左轴“千个”；计划个数生产性、实绩个数生产性 MUST 使用折线图并绑定右轴“个/MH”。表格 MUST 保留原始数量，只有图表数量 MUST 除以 `1000`。

#### Scenario: 图表固定四个系列

- **WHEN** 系统生成生产性图表
- **THEN** 图表 MUST 只包含两组数量柱和两条生产性折线
- **AND** 两条生产性折线的 `yAxisIndex` MUST 指向右轴
- **AND** 系统 MUST NOT 绘制计划 MH 或实绩 MH

### Requirement: 真实接口替换需保持日班次模型

系统 MUST NOT 猜测 `getWorkhours` 的返回结构。在获得能力、提高基础数及部门/工序级直接出勤工时的稳定契约前，生产性推移表 MUST 保持整卡固定 mock。未来接入真实数据时 MUST 使用相同的生产日与班次输入模型，并保持本规范定义的聚合、截止、显示和图表规则。

#### Scenario: 仅有计划实绩数量接口不足以切换

- **WHEN** `getPlan` 和 `getOutput` 可用，但能力、提高基础数或直接出勤 MH 契约仍有缺失
- **THEN** 系统 MUST 继续使用整卡固定 mock
- **AND** 系统 MUST NOT 把真实数量与 mock MH 混合展示

### Requirement: 真实计划实绩与生产性卡片独立并存

部门和工序维度 MUST 各展示一张“生产计划实绩推移表”，通过 `getPlan`、`getOutput` 读取真实数量，展示计划生产数、实绩生产数、实绩-计划和生产达成率。部门 MUST 汇总所属工序，工序 MUST 仅统计当前工序。该卡片 MUST NOT 使用六行生产性 mock 作为数量来源。

#### Scenario: 同时展示两类推移表

- **WHEN** 用户进入部门或工序看板
- **THEN** 系统 MUST 展示真实生产计划实绩卡片及所属工序的生产性 mock 卡片
- **AND** 只有生产性卡片 MUST 显示 mock 标识

#### Scenario: 两种卡片独立刷新

- **WHEN** 用户刷新真实生产计划实绩卡片
- **THEN** 系统 MUST 清除当月计划和实绩缓存并重新请求两个接口
- **AND** 系统 MUST 保留生产性 mock 卡片
- **WHEN** 用户刷新生产性卡片
- **THEN** 系统 MUST 只重建当前维度的生产性 mock 卡片，不请求业务接口或替换真实卡片
