# 制造日报规范

## Purpose

提供按部门、工序和数据日查询的制造日报，完整展示出勤、生产和品质，并明确数据缺口，避免实时或演示数据伪装成历史实绩。

## Requirements

### Requirement: 独立查询页面与可恢复筛选

系统 MUST 提供独立制造日报页面和部门、工序看板入口。部门必选，工序按部门支持的工序族去重；默认数据日为昨日，报告日为次日。系统 MUST 将已应用筛选写入 URL，刷新后恢复；待提交筛选 MUST NOT 改变当前日报的统计标签。

#### Scenario: 制造1课前处理

- **WHEN** 用户从前处理1或前处理2进入日报
- **THEN** 系统以制造1课＋前处理查询一次，不重复汇总相同 API 工序族

#### Scenario: 修改部门或工序自动查询

- **WHEN** 用户修改部门或工序
- **THEN** 系统 MUST 使用当前筛选自动查询四个分区并同步 URL，无需再点击“查询”；若原工序不受新部门支持，先选择新部门首个工序族，再发起一次查询
- **AND** 单独修改日期仍通过“查询”提交；随后修改部门或工序时一并提交当前日期，日期无效时提示并阻止查询

### Requirement: 跨日班次和出勤口径

出勤 MUST 展示数据日全部有效班次及报告日早班，班次时间和跨午夜归属 MUST 以接口为准。直接在籍 MUST 使用排班口径，说明保留在项目文档，出勤班长单独展示且不计入直接人数。未开始或统计中的班次 MUST NOT 据排班−出勤推算缺勤。

#### Scenario: 两日出勤只提供统计值

- **WHEN** 已验证的两日出勤端点返回班次统计，但没有起止时刻和完成状态
- **THEN** 系统展示服务端统计值与服务端出勤率，内部保留未知状态，正常展示不附加班次状态文案，不编造时刻、不据人数差推算缺勤
- **AND** 按端点约定将报告日行识别为报告日早班；每日班长名单只展示一次，不擅自分配到班次

#### Scenario: 次日早班未开始

- **WHEN** 次日早班状态为 `not_started`
- **THEN** 系统保留已知排班数，不把实绩、缺勤、分类或出勤率显示为零

#### Scenario: 缺勤分类差异

- **WHEN** 已完成班次的六类缺勤合计与缺勤总数不一致
- **THEN** 系统保留差异校验并标记数据未完成，不自动改写“其他”人数；出勤页面不显示黄色差异说明条

#### Scenario: 缺勤分类为小数及部分出勤异常

- **WHEN** 两日出勤返回0.5、1.5等非负有限分类统计值
- **THEN** 系统 MUST 保留小数展示，不按整数过滤、不取整、不擅自解释折算单位；仍对分类合计与缺勤总数进行差异校验，不显示黄色说明条
- **AND** 班长名单缺失不得阻止直接人员统计展示；日期/班次异常和重复班次应排除并保留内部说明，其他有效班次继续展示，全部无效时分区报错

### Requirement: 出勤区域仅展示参考图内容

正常加载的出勤区 MUST 仅展示出勤实绩标题、出勤班长、直接人员出勤及班次/在籍/实绩/出勤率/缺勤/六类原因表。MUST NOT 展示口径说明、更新时间、统计范围、完整性徽标、班次状态、异常说明和重新读取按钮；失败仍需可识别及可重试。

#### Scenario: 日期分组与真实空值

- **WHEN** 接口返回数据日班次及报告日早班
- **THEN** 日期和星期按同日合并，位于“班次”组合表头下，视觉 MUST 复用项目卡片、数值组件和表格样式，使用设计变量定义的表面、浅蓝、边框及危险色，保持字号和间距一致
- **AND** 分类真实0留白，非零小数保留，缺失或无效数值显示“—”；班长空数组时姓名区留白，不能补造姓名
- **AND** 图片样例不构成出勤率告警阈值，未确认规则前不按样例任意标红出勤率

### Requirement: 生产数量公式与原始比例

生产上表 MUST 按日期、部门、工序过滤后以zhifan分组，取计划、实绩、不良记录的制番并集排序，相同制番跨设备和班次合计。缺少制番的记录不得生成示例名称，相关小计标记部分并保留内部说明。洗净/粘接仅为示意，不要求该分类。

生产区流动数 MUST 为ΣgetOutput.number；废弃数 MUST 为ΣgetRejects.number全部类型；不良数 MUST 仅统计type=不良；合格数 MUST 为流动数加明确type非不良数量；实绩数 MUST 为流动数加废弃数。达成率为实绩÷计划，合格率为合格÷实绩。产线按设备分组使用相同公式。品质区 MUST 共用相同实绩、合格、不良公式及空值规则；主体不良率与原因不良率分别为不良数或原因不良数÷同一主体含废弃实绩。

#### Scenario: 不良接口成功无记录

- **WHEN** 不良来源成功且范围完整，整月、当前制番/产线或某分类无记录
- **THEN** 生产与品质对应不良、废弃及非不良分类数量为0，无需取得非空样本才开发
- **AND** 计划/实绩无记录仍保留缺失，品质区不良空数组同样按0

#### Scenario: 不良类型与计算完整性

- **WHEN** 不良记录有非空且不等于“不良”的type
- **THEN** 生产区将它计入非不良及废弃，不限制为“其它/其他”白名单
- **AND** type缺失或空白时可计入有效废弃总数，但不能当作明确非不良；分类结果为缺失或部分
- **AND** 源失败、无效数量、日期或归属不明不得转成0；加法任一来源缺失则结果缺失，部分来源只能形成部分结果，不参与比率和排行

#### Scenario: 设备即产线及时间展示

- **WHEN** 生产接口包含shebei，设备日报包含deviceCode/deviceName
- **THEN** 系统直接按设备编码关联产线，显示名称；名称缺失回退设备编码，无需新增生产线映射
- **AND** 保留总运转、生产、阻碍时间，移除计划停止时间列，不推算缺失时间

#### Scenario: 可动率与阻碍占比原值

- **WHEN** 设备日报返回availabilityRate或阻碍项ratio
- **THEN** 生产区直接显示原始数值，保留小数，不换算、不重新计算、不附百分号；0.845显示0.845，84.5显示84.5，0显示0
- **AND** 缺失显示“—”；单位及分母未明确不阻碍展示

#### Scenario: 缺失输入

- **WHEN** 比率输入缺失、未完成、口径不明确或分母不大于零
- **THEN** 系统显示 `—`，不得以零、平均百分比或演示值替代

#### Scenario: 数量字符串与部分有效记录

- **WHEN** schedule返回Swagger示例中的十进制数量字符串或夹杂无效记录
- **THEN** 数量字符串 MUST 经显式校验后转为非负安全整数；空字符串、null、非十进制、非整数及不安全整数不得作为有效数量
- **AND** 系统 MUST 保留有效记录，部分数值、日期、归属或不良分类不明时仅展示已确认小计并标记partial，不参与比率或排行；全部无效保留缺失，不能补零
- **AND** 品质明细存在制番缺失时，相关数量不得视为完整排行输入

### Requirement: 排行与业务范围

生产排行 MUST 选择完整业务范围内达成率低于90%的最低三项且排除零计划。品质排行 MUST 选择实绩>0、不良>0的最高三项；具有模具关联时加硫按模具，其他工序按制番。相同比率按稳定业务编码排序。日报统计范围 MUST NOT 受地图显示白名单限制。生产区设备即产线，无需另建映射；品质区缺模具关联时 MUST 明示实际展示维度。

#### Scenario: 加硫模具排行

- **WHEN** 加硫数据提供完整模具关联并声明模具维度
- **THEN** 按模具汇总其关联制番的数量再排名；不能将截断的制番榜转换为模具榜，拒绝声明与行数据维度不一致的响应

#### Scenario: 设备产线与制番品质数据

- **WHEN** 已验证来源只有设备计划/实绩和制番记录，没有模具关联
- **THEN** 系统以产线生产与阻碍、制番品质明细展示并声明维度；生产仅显示有效排行；品质缺完整排行输入时在同一表格显示已有真实明细但名次为“—”，有排名时只显示最高三项

#### Scenario: 细分工序与未知归属

- **WHEN** 月记录中存在前处理1、前处理2、仕上检查、出货检查包装
- **THEN** 前处理1、前处理2归并为前处理，仕上检查、出货检查包装归并为后处理，按数据日和部门统计全部匹配记录
- **AND** 日报选择器 MUST 支持已确认的历史归属，包括制造2课的后处理检查记录，即使地图未配置该工序；无对应地图工序时返回部门看板
- **AND** 未知工序或缺少归属不能静默漏算；已知部分可显示但标记不完整，不能用于排行。不良缺少部门/工序时只能用同月记录中设备的唯一历史归属关联，不覆盖其显式字段

#### Scenario: 原因超出默认数量

- **WHEN** 品质现象超过两项
- **THEN** 品质表格仅显示前两项现象，不提供图外的展开/收起操作；其他现象保留在显示模型中

### Requirement: 分区可靠性和真实数据边界

四个数据资源 MUST 独立加载、失败和重试，保留时间来源、工厂时区、统计范围及完整性。出勤区按参考图精简；生产汇总与排行合并在一个视觉分区，正常元信息、缺口说明及展开入口不展示，缺口保留在文档中；品质区同样隐藏正常元信息、说明及展开入口。新查询和刷新 MUST 使旧响应失效，卸载 MUST 停止发布结果。日报 MUST NOT 使用 mock 降级；允许将已核验的现有接口适配为显示模型，并明确声明、实测和未验证字段的边界，不请求未发布的预定义日报端点。

#### Scenario: 部分来源失败与共享请求

- **WHEN** 设备时长源失败但生产计划/实绩可用，或多个分区读取同月记录
- **THEN** 页面保留可用真实数据，提示失败来源并允许重试；仅共享进行中的请求，不缓存已完成结果
- **AND** 单区取消不得影响其他订阅分区，全部订阅者取消才中断上游；全部必要来源失败时显示分区错误

#### Scenario: 缺少源更新时间

- **WHEN** 原始接口未提供更新时间或统计起止时刻
- **THEN** 页面只标实际读取时间、已知数据归属日和时区，不生成虚假的源更新时间或班次边界

#### Scenario: 来源成功但无记录或设备全零

- **WHEN** 来源成功返回空数组、仅有其他日期范围的记录，或匹配设备的运转/生产/阻碍时长全为0
- **THEN** 系统 MUST 在内部说明中区分整月未返回、当前条件无匹配或设备时间全零；生产不良成功空记录按0，其他来源维持既有缺失规则；全零时间按原值显示，不宣称采集已完整

#### Scenario: 后端尚未接入

- **WHEN** 某接口返回404、501或明确未接入业务码
- **THEN** 对应分区显示“数据未接入”与重试，其余分区正常处理；网络错误显示“加载失败”而不是无业务记录

#### Scenario: 查询快速切换

- **WHEN** 用户切换部门或日期后上一请求才完成
- **THEN** 旧结果被忽略，不能混入新日报

### Requirement: 宽屏可读与历史查询边界

页面 MUST 全宽纵向展示，在1920px和2K下保持可读字号；生产排行按参考图纵向排列，每项左侧数量/时间、右侧阻碍表。窄屏 MUST 使用局部横向表格滚动，不撑宽页面。首版只读查询，历史结果反映当前查询数据，不承诺发布快照，不提供填报、审批、导出或归档。

### Requirement: 生产实绩参考图与真实数据边界

生产区 MUST 复用ReportSection、MetricValue、项目表格样式和设计变量，展示首列为“制番”的九列表格；“前日”“含不良”“达成率最差生产线（90%以下）”均是原型红字说明，MUST NOT 展示。排行每项包含生产线名称、计划、实绩、达成率、总运转/生产/阻碍时间、可动率及阻碍项目/时间/次数/占比，最多三项，不以示例填充，保留数量及时间单位、数据单元格告警样式。

#### Scenario: 制番与产线展示

- **WHEN** 接口返回zhifan及shebei/deviceCode
- **THEN** 汇总按制番分行，排行主体标为生产线；不得生成洗净/粘接样例行或显示红字排行说明标题
- **AND** 合格、流动按已确认公式显示；计划停止列略过；已返回时间0显示0.00；阻碍空数组以“—”占位，不补造原因

#### Scenario: 生产汇总与排行独立状态

- **WHEN** 汇总失败而排行成功，或排行失败而汇总成功
- **THEN** 同一生产区内成功部分仍可见，失败部分可独立重试；正常数据说明及重新读取按钮不展示
- **AND** 无完整排名输入时不生成卡片，不展示额外空态说明、全部明细及展开入口；不足三项不显示虚假No.2/No.3

#### Scenario: 删除原型之外的正常展示内容

- **WHEN** 生产数据正常加载
- **THEN** MUST NOT 展示数据说明、时间元信息、来源归属说明、设备编码副行、全部明细、原因展开及重新读取按钮；阻碍仅显示前三项，缺失项显示“—”，保留原图单位与列标题

### Requirement: 品质区域仅展示参考图表格

品质区 MUST 复用项目卡片、数值组件、表格样式和设计变量，显示标题、数量单位和九列表格；每个主体两行不良现象，主体信息合并单元格，第一项现象使用浅黄色底色。MUST NOT 显示红字原型说明、元信息、徽标、额外口径说明、全部明细和现象展开按钮。

#### Scenario: 品质排行及真实空值

- **WHEN** 存在完整有效的主体实绩和不良数量
- **THEN** 按已定义不良率降序展示最高三项，No.1–No.3只对应真实排名；现象不良率分母为同一主体实绩
- **AND** 合格数按共用公式显示，现象缺失显示“—”；设备即产线，无模具关联时按制番展示，不复制原型中的示例数值

#### Scenario: 品质没有排名输入或不良全零

- **WHEN** 不良来源成功无记录且存在有效实绩，或不良率均为0
- **THEN** 在相同九列表格中保留真实明细，名次显示“—”，不良数为0、不良率为0.00%，不生成No.排名
- **AND** 没有任何记录时只保留表头及“—”；请求失败仍可识别并可重试

#### Scenario: 品质产线名称及部分来源失败

- **WHEN** 同日、同部门、同工序的设备日报能以唯一deviceCode关联品质记录的shebei
- **THEN** 显示deviceName，多条产线按设备编码排序；缺失、重复或名称来源失败时回退设备编码，不改变有效数量及排行
- **AND** 品质和生产共享进行中的月源、设备源及取消引用计数；实绩/不良源同时失败则品质区报错，名称可用不能掩盖数量源失败

#### Scenario: 品质制番范围和真实现象

- **WHEN** 品质读取所选范围的实绩和不良记录
- **THEN** 以二者制番并集生成明细，同制番跨设备班次合计，不加入仅有计划的制番；无模具关联时加硫也按制番
- **AND** 仅取 `type=不良` 的 `yuanyin` 为现象名称，同制番同名现象跨设备、班次汇总 `number`，按数量降序、并列按名称稳定排序；表格仅显示前两项，现象不良率为现象数量÷同一制番含废弃实绩
- **AND** “其它”等非不良类型不进入不良分子和现象；仍按生产数量公式计入废弃及明确非不良，不改变主体实绩分母
- **AND** 现象名称缺失不得伪造或分摊总不良，已知现象仅显示部分小计，不计算现象不良率；源失败、无效数量或归属不完整不得补零；成功无不良记录返回空现象列表，页面缺项显示“—”

#### Scenario: 日不良查询与请求隔离

- **WHEN** 生产、产线及品质读取日报不良记录
- **THEN** `/schedule/getRejects` MUST 同时传必填 `month=YYYY-MM` 和所选 `date=YYYY-MM-DD`，并继续校验响应日期、部门、工序及历史设备归属；计划和实绩保持整月查询用于归属关联
- **AND** 仅相同月份及日期的不良请求可共享；同月不同日期 MUST NOT 复用日不良结果，单区取消不得中断其他订阅者；通用月查询省略date时保持整月语义
