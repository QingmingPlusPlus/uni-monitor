# 制造日报规范

## Purpose

提供按部门、工序和数据日查询的制造日报，完整展示出勤、生产和品质，并明确数据缺口，避免实时或演示数据伪装成历史实绩。

## Requirements

### Requirement: 独立查询页面与可恢复筛选

系统 MUST 提供独立制造日报页面和部门、工序看板入口。部门必选，工序按部门支持的工序族去重；默认数据日为昨日，报告日为次日。系统 MUST 将已应用筛选写入 URL，刷新后恢复；待提交筛选 MUST NOT 改变当前日报的统计标签。

#### Scenario: 制造1课前处理

- **WHEN** 用户从前处理1或前处理2进入日报
- **THEN** 系统以制造1课＋前处理查询一次，不重复汇总相同 API 工序族

#### Scenario: 修改部门或工序自动查询

- **WHEN** 用户修改部门或工序
- **THEN** 系统 MUST 使用当前筛选自动查询四个分区并同步 URL，无需再点击“查询”；若原工序不受新部门支持，先选择新部门首个工序族，再发起一次查询
- **AND** 单独修改日期仍通过“查询”提交；随后修改部门或工序时一并提交当前日期，日期无效时提示并阻止查询

### Requirement: 跨日班次和出勤口径

出勤 MUST 展示数据日全部有效班次及报告日早班，班次时间和跨午夜归属 MUST 以接口为准。直接在籍 MUST 使用排班口径并注明，出勤班长单独展示且不计入直接人数。未开始或统计中的班次 MUST NOT 据排班−出勤推算缺勤。

#### Scenario: 两日出勤只提供统计值

- **WHEN** 已验证的两日出勤端点返回班次统计，但没有起止时刻和完成状态
- **THEN** 系统展示服务端统计值与服务端出勤率，标明状态未提供，不编造时刻、不据人数差推算缺勤
- **AND** 按端点约定将报告日行识别为报告日早班；每日班长名单只展示一次，不擅自分配到班次

#### Scenario: 次日早班未开始

- **WHEN** 次日早班状态为 `not_started`
- **THEN** 系统显示“未开始”，保留已知排班数，不把实绩、缺勤、分类或出勤率显示为零

#### Scenario: 缺勤分类差异

- **WHEN** 已完成班次的六类缺勤合计与缺勤总数不一致
- **THEN** 系统提示核对并标记数据未完成，不自动改写“其他”人数

### Requirement: 独立权威数量与时间比率

合格、流动、不良、废弃 MUST 独立取权威数据，MUST NOT 互相相减补造。达成率为实绩÷计划；合格率、不良率为对应数量÷实绩；可动率 MUST 为生产时间÷已扣除计划停止的可运转时间。品质原因不良率 MUST 为该原因不良数÷同一排行主体实绩。

#### Scenario: 废弃分类与缺失数量

- **WHEN** 服务端明确废弃为不良加其他，且同范围记录分类和数量有效
- **THEN** 系统可以按该已声明口径求和；分类未知、未返回记录或归属不明时保留缺失或部分状态，不把空数组补为零
- **AND** 合格数、流动数仍须独立来源，不能由实绩减不良或废弃生成

#### Scenario: 设备时间没有明确比例单位

- **WHEN** 设备日报仅提供总运转时间、生产时间、阻碍时间及未说明单位的比率
- **THEN** 系统按明确的小时单位展示时间，比率标明原始值；不得把总运转时间当成已扣计划停止的可运转时间，也不得猜测百分比单位

#### Scenario: 时间可动率

- **WHEN** 可运转23小时、计划停止1小时、生产19.44小时
- **THEN** 可动率显示84.5%，不再次从23小时扣1小时

#### Scenario: 缺失输入

- **WHEN** 比率输入缺失、未完成、口径不明确或分母不大于零
- **THEN** 系统显示 `—`，不得以零、平均百分比或演示值替代

### Requirement: 排行与业务范围

生产排行 MUST 选择完整业务范围内达成率低于90%的最低三项且排除零计划。品质排行 MUST 选择实绩>0、不良>0的最高三项；具有模具关联时加硫按模具，其他工序按制番。相同比率按稳定业务编码排序。日报统计范围 MUST NOT 受地图显示白名单限制。缺少生产线或模具关联时 MUST 明示实际展示维度，不得伪装为设计中的聚合维度。

#### Scenario: 加硫模具排行

- **WHEN** 加硫数据提供完整模具关联并声明模具维度
- **THEN** 按模具汇总其关联制番的数量再排名；不能将截断的制番榜转换为模具榜，拒绝声明与行数据维度不一致的响应

#### Scenario: 只有设备或制番的真实数据

- **WHEN** 已验证来源只有设备计划/实绩和制番记录，没有权威生产线或模具关联
- **THEN** 系统以设备生产与阻碍、制番品质明细展示并声明维度；缺完整排行输入时仍显示已有真实明细，有排名时可以查看全部记录

#### Scenario: 细分工序与未知归属

- **WHEN** 月记录中存在前处理1、前处理2、仕上检查、出货检查包装
- **THEN** 前处理1、前处理2归并为前处理，仕上检查、出货检查包装归并为后处理，按数据日和部门统计全部匹配记录
- **AND** 日报选择器 MUST 支持已确认的历史归属，包括制造2课的后处理检查记录，即使地图未配置该工序；无对应地图工序时返回部门看板
- **AND** 未知工序或缺少归属不能静默漏算；已知部分可显示但标记不完整，不能用于排行。不良缺少部门/工序时只能用同月记录中设备的唯一历史归属关联，不覆盖其显式字段

#### Scenario: 原因超出默认数量

- **WHEN** 生产原因超过三项或品质现象超过两项
- **THEN** 页面提供展开全部和收起操作，不丢弃其余原因

### Requirement: 分区可靠性和真实数据边界

四个分区 MUST 独立加载、失败和重试，显示时间来源、工厂时区、统计范围及完整性。新查询和刷新 MUST 使旧响应失效，卸载 MUST 停止发布结果。日报 MUST NOT 使用 mock 降级；允许将已核验的现有接口适配为显示模型，并明确声明、实测和未验证字段的边界，不请求未发布的预定义日报端点。

#### Scenario: 部分来源失败与共享请求

- **WHEN** 设备时长源失败但生产计划/实绩可用，或多个分区读取同月记录
- **THEN** 页面保留可用真实数据，提示失败来源并允许重试；仅共享进行中的请求，不缓存已完成结果
- **AND** 单区取消不得影响其他订阅分区，全部订阅者取消才中断上游；全部必要来源失败时显示分区错误

#### Scenario: 缺少源更新时间

- **WHEN** 原始接口未提供更新时间或统计起止时刻
- **THEN** 页面只标实际读取时间、已知数据归属日和时区，不生成虚假的源更新时间或班次边界

#### Scenario: 后端尚未接入

- **WHEN** 某接口返回404、501或明确未接入业务码
- **THEN** 对应分区显示“数据未接入”与重试，其余分区正常处理；网络错误显示“加载失败”而不是无业务记录

#### Scenario: 查询快速切换

- **WHEN** 用户切换部门或日期后上一请求才完成
- **THEN** 旧结果被忽略，不能混入新日报

### Requirement: 宽屏可读与历史查询边界

页面 MUST 全宽纵向展示，在1920px和2K下保持可读字号及生产线三列卡片；窄屏 MUST 使用单列和局部横向表格滚动。首版只读查询，历史结果反映当前查询数据，不承诺发布快照，不提供填报、审批、导出或归档。
