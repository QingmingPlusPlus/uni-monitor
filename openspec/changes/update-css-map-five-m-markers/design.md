## Context

css-map 同时维护两个设备卡片渲染路径：默认路径由 `spriteCssMapDeviceCard.ts` 在 Canvas 上绘制后交给 Three.js Sprite，WebGL 不可用时由 `CssMapEquipmentNode.vue` 和 `CssMapFiveMMarker.vue` 以 DOM/CSS 回退。两个路径共用 `css3dMapPalette.ts` 中的 5M glyph，但当前标记背景分别硬编码为同一种深蓝色圆角方块。

地图右上图例由 `CssMapLegend.vue` 独立覆盖在地图之上，已有负荷率六档和工况五类。新增五行 5M 图例后，总高度可能超过最小高度地图的可用区域，还需避让右下角地图操作控件。

## Goals / Non-Goals

**Goals:**

- 为五类 5M 变化点建立唯一、共享、可测试的颜色与文字色映射。
- 在 DOM 与 Canvas 中绘制轮廓、填充和正向文字一致的菱形标记。
- 在现有图例下方提供完整的 5M 类型说明，并在空间不足时保持可滚动访问。
- 保留现有 5M 数据、布局容量、开关和 `+N` 溢出行为。

**Non-Goals:**

- 不调整 `GET /schedule/getChangePoint` 接口、类型识别或设备匹配逻辑。
- 不改变人员扇形标记、工况色、负荷率色或地图操作方式。
- 不为 5M 增加筛选、点击、详情弹窗或动画。
- 不重新设计整个图例的位置和表格结构。

## Decisions

### 1. 使用共享的 5M 视觉方案作为唯一颜色来源

在 `css3dMapPalette.ts` 中按 `CssMapFiveMCategory` 导出包含 glyph、填充色和文字色的视觉方案，供 DOM 标记、Canvas 标记和图例共同使用。采用以下主题协调后的固定映射：

| 类别 | glyph | 填充色 | 文字色 |
| --- | --- | --- | --- |
| `man` | 人 | `#7C3FA1` | `#FFFFFF` |
| `machine` | 机 | `#C9363E` | `#FFFFFF` |
| `material` | 料 | `#2E8B3C` | `#FFFFFF` |
| `method` | 法 | `#162033` | `#FFFFFF` |
| `environment` | 环 | `#F5D90A` | `#162033` |

菱形描边使用界面的 operation 色，保持参考图中的冷色轮廓，但采用细描边而非高饱和粗边。黄色使用深色文字，其余类别使用白色文字，以保证小尺寸标记的可读性。

备选方案是继续由 DOM 和 Canvas 各自硬编码颜色；该方案容易产生颜色漂移，也无法让图例复用同一映射，因此不采用。

### 2. 绘制真实菱形轮廓，文字不随图形旋转

DOM 标记使用覆盖完整标记盒的四点菱形轮廓，并将 glyph 作为独立层正向居中；Canvas 使用相同的上、右、下、左四点路径绘制。这样能够在不改变 marker slot 外接尺寸的前提下保持文字正向，并避免通过整体 `rotate(45deg)` 后再反向旋转文字造成的尺寸与抗锯齿差异。

两种渲染路径都保留当前随设备卡片缩放得到的 marker size。描边固定为视觉上的细线，小尺寸不增加复杂渐变；阴影仅允许作为轻量层次，不得降低 glyph 清晰度。

备选方案是旋转圆角方块。该方案的外接尺寸会扩大，容易挤压现有横向五槽和纵向三列布局，因此不采用。

### 3. 图例复用共享视觉方案并保留现有分组顺序

`CssMapLegend.vue` 在负荷率、工况两张表之后新增第三张表，表头固定为“颜色”和“5M变化点”，行顺序固定为人、机、料、法、环。色样使用与设备卡片一致的菱形，而不是矩形色块，使图例同时解释形状和颜色。

图例容器增加基于地图可用高度的最大高度与纵向滚动，并为右下角地图操作控件保留空间。宽屏和弹窗中空间充足时仍一次展示全部内容；空间不足时只滚动图例自身，不滚动或移动地图。

备选方案是压缩全部图例行高以强制一次展示。该方案会降低 2K 触摸大屏以外的小尺寸场景的可读性，因此不采用。

### 4. `+N` 保持中性汇总样式

`+N` 表示未逐一绘制的变化点数量，不对应任何单一 5M 类别，因此继续使用当前中性汇总文本，不绘制成某一种颜色的菱形。现有纵向六槽、横向五槽的容量计算不变。

## Risks / Trade-offs

- [红、绿、黄也用于工况或负荷率，可能产生颜色语义重叠] → 通过菱形轮廓、居中 glyph 和新增 5M 图例形成独立视觉语法。
- [菱形在最小 marker size 下的有效填充面积小于方块] → 保持轮廓覆盖完整 marker slot，使用高对比文字与简洁细描边，并通过真实设备尺寸视觉验证。
- [新增图例使右上覆盖层变高] → 限制图例最大高度、避让操作控件并启用容器内纵向滚动。
- [DOM 与 Canvas 抗锯齿表现无法逐像素一致] → 以共享颜色、相同几何点、glyph、尺寸和语义一致为验收标准，不要求逐像素一致。

## Migration Plan

1. 先加入共享 5M 视觉方案及单元测试。
2. 分别切换 DOM 与 Canvas 标记绘制，并验证布局容量未变化。
3. 增加第三组图例和高度不足场景处理。
4. 运行 css-map 相关测试、类型检查和 H5 构建，并在 mock 5M 数据下检查普通地图与展开地图。
5. 同步项目规范和现状文档后发布。该变更不涉及数据迁移；若需回滚，可恢复旧标记绘制和第三组图例，不影响接口或缓存数据。

## Open Questions

无。颜色、行顺序、溢出行为和响应式处理均已在本设计中确定。
