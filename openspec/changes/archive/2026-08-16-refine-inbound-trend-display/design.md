## Context

入库计划实绩推移卡片当前复用 `trendPeriodBuilder.ts` 和 `flowTrendCommon.ts`：周期构造同时服务入库与生产计划趋势，默认生成月列、月周配置中的全部周列和当前周工作日日列；展开视图还会增加整月日列。图表直接把表格数值映射为 ECharts series，因此数值 `0` 会被绘制。

本次低保真口径只针对入库计划实绩推移表。它要求月内周段稳定使用七日分桶、增加“截止当天”累计列、保留当前周全部自然日，并让图表在不改变时间顺序的前提下隐藏零值和断开折线。通用 `TableChartCard` 仍只负责展示，不承担入库业务计算。

## Goals / Non-Goals

**Goals:**

- 为入库趋势生成全月、截止当天、存在的月内周段和当前周每日周期。
- 让相同周期结构同时驱动紧凑表格和展开表格。
- 为入库趋势图提供可测试的非零有效点、首尾裁剪、内部断线和空系列规则。
- 保持生产计划趋势、出勤率趋势、接口过滤和缓存刷新行为不变。
- 通过可控业务日期验证月初、月末、二月和零值边界。

**Non-Goals:**

- 不增加低保真图中的计划 MH、实绩 MH、生产性行、每日系数或顶部目标值。
- 不修改入库 API、部门过滤、工序归属或月级缓存协议。
- 不为通用 `TableChartCard` 内置入库字段、日期计算或零值业务语义。
- 不把本次周期口径自动推广到生产计划和出勤率推移表。
- 不要求复刻低保真图的合并表头、颜色和像素级样式。

## Decisions

### 1. 使用入库专用周期构造策略

新增入库专用的周期构造入口，或为现有周期构造器增加显式且默认关闭的入库策略。入库策略按设备本地业务日期生成以下顺序：

1. `month`：当前月全月；
2. `toDate`：当月 1 日至业务当天，包含当天；
3. `week1` 至当月实际存在的最后一个周段；
4. 业务当天所在周段的全部自然日日列。

紧凑视图与展开视图使用同一周期数组，避免展开后出现额外整月日列。周期类型需要能够区分 `month` 与 `toDate`，从而让表格保留两列，而图表同时排除两种累计点。

备选方案是直接修改 `createTrendPeriods()` 的全局默认行为。该方案会同步改变生产计划和出勤率趋势，超出本次范围，因此不采用。

### 2. 入库周段固定为月内七日分桶

入库周段不使用 ISO 周一至周日回退，而固定为：

- `1W`：1–7 日；
- `2W`：8–14 日；
- `3W`：15–21 日；
- `4W`：22–28 日；
- `5W`：29 日至月末。

只有月份包含第 29 日时才生成 `5W`，任何月份都不得生成 `6W`。当前周日列包括周六、周日，并裁剪在当月边界内。例如 2026-08-01 生成日列 1–7；2026-08-31 只生成日列 29–31。

备选方案是继续完全依赖 `/basic/month-segment/base-data` 或自然周回退。该方案可能生成非 1–7 分桶甚至 `6W`，无法稳定匹配低保真口径，因此入库显示周期不采用该方案。现有月周配置继续供其他推移表使用。

### 3. 各累计列独立选择日记录

`month` 聚合当月全部日记录；`toDate` 只聚合 `day <= currentDay` 的记录；周列聚合对应完整周段；日列只聚合对应单日。计划、实绩、实绩计划差和达成率继续复用现有聚合规则，空记录保持 `null`，真实零值在表格中保持 `0`。

不对输入记录做全局“截止当天”过滤，因为这会错误截断全月和未来周计划；截止范围只属于 `toDate` 周期本身。

### 4. 图表采用非零有效点投影并保留内部时间缺口

入库图表继续只展示计划入库数、实绩入库数和入库达成率，不展示实绩计划差。图表周期只取周列与当前周日列，排除 `month` 和 `toDate` 两个累计列。

对每条 series：

- 只有有限数值且大于 `0` 的值是有效点；
- `0`、空值和非有限值映射为 `null`；
- 完全没有有效点的 series 从 `chartData.series` 移除，由现有 `replaceMerge` 更新策略清除旧图例和旧曲线；
- 所有系列共同确定第一个与最后一个有效类目，裁掉这一区间外的首尾空类目；
- 第一个与最后一个有效类目之间的空类目必须保留，以承载 `null` 并形成可见断线；
- 入库折线显式设置 `connectNulls: false`，不得跨零值或空值连接。

仅删除所有空类目会把零值两侧的点变成相邻点并重新连线，因此不采用。完全保留所有未来空类目又会制造无数据横轴，因此采用“裁首尾、留内部缺口”的折中。

### 5. 业务日期保持可测试

周期构造接收可选业务日期或通过已有可替换时间入口读取设备本地日期，生产调用使用当前本地日期，测试传入或冻结具体日期。日期参数不得从接口记录的最大日期推断，否则未来计划数据会错误推进“截止当天”和当前周。

## Risks / Trade-offs

- [Risk] 入库固定周段与后端月周配置不一致。→ 将固定分桶限定在入库显示层，并在项目文档明确该卡片特例；其他推移表继续使用既有配置。
- [Risk] `0` 可能代表真实的零入库。→ 表格继续显示 `0`，只在图表中按用户要求隐藏并断线。
- [Risk] 动态移除空 series 后，ECharts 可能残留旧图例或曲线。→ 继续使用 `replaceMerge: ["xAxis", "dataset", "series"]`，增加由有数据变为全空的更新测试。
- [Risk] 首尾裁剪与内部缺口处理错误会造成横轴和 series 长度不一致。→ 以统一索引窗口同时切片 `xAxisData` 和所有 series，并覆盖前空、中空、后空场景。
- [Risk] 共享函数修改会回归生产计划趋势。→ 优先新增入库专用适配器；若抽取共享纯函数，必须由显式策略启用并运行两类卡片回归测试。

## Migration Plan

1. 先增加周期和图表投影的纯函数测试，固定预期列与断线行为。
2. 接入入库 loader，保持 API 请求、过滤和缓存逻辑不变。
3. 同步紧凑与展开视图数据，并验证 ECharts series 缩减更新。
4. 运行入库、生产计划、出勤率和通用表图组件相关测试及类型检查。
5. 更新接口映射、维度和必要的共享工具文档；若出现回归，可回退入库专用周期/投影入口而不影响接口层。
