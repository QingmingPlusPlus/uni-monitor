## Context

当前人员出勤情况表由部门和工序看板共用。`GET /attendance/attendanceSituation` 返回班次、`positionType`、`positionName`、在籍人数和实际出勤人数；loader 先按 `positionType` 区分直接/间接，再以 `positionName` 中文关键词拆分组长、派遣、临时和顶岗，未命中的直接人员作为正式工兜底。

表格数据模型、真实接口聚合、mock、班次/工序/部门合计和 CSS Grid 列跨度是彼此耦合的。新增一列必须同步调整这些位置，否则会出现新人仍落入正式工、合计行缺值或表头与数据错列。

## Goals / Non-Goals

**Goals:**

- 在不修改接口端点、查询参数和响应外形的前提下识别并展示新人。
- 保持新人、正式工和直接在籍合计之间的数量守恒。
- 让班次、工序合计、部门全体合计、紧凑表和展开表采用同一新人数据源。
- 保持现有出勤人数和出勤率口径不变。

**Non-Goals:**

- 不重命名现有“临时工”为参考图中的“期间工”。
- 不移除或改变现有“顶岗”列。
- 不改变出勤率推移表、人员明细卡片或信息汇总的展示规则。
- 不在本次变更中重构全部人员子类为新的后端枚举协议。

## Decisions

### 1. 沿用现有 `positionName` 关键词分类契约

新人只在记录属于直接人员、不是班长且 `positionName` 包含“新人”时匹配。这样与组长、派遣、临时和顶岗的现有分类方式一致，也不需要扩展请求或响应结构。

备选方案是增加新接口字段或扩展 `positionType`。该方案会改变当前 API 契约，且仓库现有 `positionType` 仅承担直接/间接一级分类，因此不在本次前端变更中采用。

### 2. 在行模型中增加显式新人字段

人员出勤行模型增加 `directNewcomer`，真实 loader、mock 模板和所有合计函数都显式处理该字段。相比在组件中临时派生数值，显式字段能确保所有层级合计可测试，并让视图只负责展示。

### 3. 新人从正式工兜底中扣除，整体指标仍由原始直接记录计算

聚合时先计算新人数量，再把它加入已识别直接人员数量；正式工继续使用“直接在籍合计减去已识别直接人员”的兜底公式。直接在籍合计和直接实际出勤人数仍直接汇总所有非班长的 `direct` 记录，不从子类字段反算，从而避免新增分类改变出勤率。

### 4. 新人作为最后一个直接在籍子类

现有列保留，数据列顺序调整为：组长、正式工、派遣工、临时工、顶岗、新人、合计、实际出勤人数、出勤率。新人位于顶岗之后、直接合计之前，符合“合计前新增新人列”的参考位置，同时不删除当前产品已有列。

CSS Grid 从 13 个数据列扩展为 14 个：直接分组表头覆盖第 6 至 14 列，直接在籍表头覆盖第 6 至 12 列，实际出勤表头覆盖第 13 至 14 列；最后一行边框选择器同步按 14 个单元格计算。移动端、桌面端和展开态使用相同列结构，只保留各自字号与行高差异。

### 5. 用聚合测试和布局检查保护数量与对齐

在现有 loader 测试中加入新人接口记录，断言新人值、正式工排除新人、工序/部门合计以及整体在籍和出勤率不变。mock 数据补齐新人字段以满足完整模型。布局通过表头/数据单元格顺序检查以及浏览器视觉检查确认 14 列对齐。

### 6. 用语义修饰类表达岗位表头类别色

为组长、正式工、派遣工、临时工和新人末级表头分别增加语义修饰类，并使用与低保真参考一致的绿、蓝、橙、黄、紫红色相。颜色使用更高饱和度的实色底色，继续使用深色主文本以保持可读性和远距离辨识度。

类别色只表达岗位类别且只应用于最下层岗位表头。班长暂不着色；参考图没有顶岗类别，因此顶岗也保持原有表头颜色。直接/间接、在籍/出勤等分组表头和所有数据单元格均不继承类别色，避免颜色被误解为数值状态或告警等级。紧凑态和展开态共用同一模板和修饰类，不维护两套配色。

## Risks / Trade-offs

- [后端返回的新人文本不包含“新人”] → 实施前用线上响应或后端约定确认实际 `positionName`；若值不同，只调整集中匹配规则和测试样例，不改变规格与数据流。
- [关键词分类仍可能遇到复合职务名称] → 保持班长优先排除，并为新人和正式工去重添加单元测试；全面互斥分类留给后续稳定枚举改造。
- [紧凑卡片增加一列后单列变窄] → 等比例扩展直接在籍列并在现有响应式断点下检查可读性；不通过隐藏列解决。
- [岗位类别色与状态色语义混淆] → 只在带明确岗位文字的表头使用类别色，数据区和班长、顶岗继续使用中性底色，不用这些颜色表达出勤状态。

## Migration Plan

1. 先更新数据模型、真实聚合、mock 和测试，确保数量守恒。
2. 再更新表格模板、岗位表头类别色及 CSS Grid 跨度，完成紧凑态和展开态视觉检查。
3. 同步接口映射、接口缺口和记忆路由文档后运行类型检查与相关测试。
4. 该变更不包含数据迁移；回滚时恢复前端字段、聚合和列布局即可，后端接口无需回滚。
