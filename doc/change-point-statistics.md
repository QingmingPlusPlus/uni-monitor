## 接口分析结论

`GET /schedule/getChangePoint` 是变化点明细查询，不是已聚合的统计接口。契约具备开始日期、类别和序号，可在确认历史完整性及唯一键后派生五类日统计；参考图包含“模具”，现有契约仅定义人、机、料、法、环，因此不能完整复刻六类数据。处置率可尝试用全部与已关闭两个查询集合计算，但尚未联调，且不能恢复历史截止日的状态。

建议部门页显示本部门汇总，工序页显示当前工序；它本身是汇总卡，但不等于不区分维度。全厂汇总可作为明确标注范围的独立入口，暂不建议在所有维度显示相同数据。设备页只适合作为设备关联明细的下钻。

## 已确认契约

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `dept` | 否 | 科室 `1/2/3/4`。 |
| `process` | 否 | 中文工序：`前处理1/前处理2/加硫/后处理`；不是其他接口的 `processType` 英文枚举。 |
| `progress` | 是 | `1` 已关闭、`0` 进行中、空值查询所有。查询所有建议显式发送 `progress=`；省略参数、字符串 `null` 是否接受未验证。 |

9月20日新增 `beginDate/endDate/banci`，分别表示开始日期、结束日期、班次（早/夜），空值表示全部。Swagger将六个参数均标必填，但实际只传progress=也成功；新日期/班次筛选行为本次未验证。仍无month、设备或工厂查询参数。

| 字段 | Swagger 描述 | 可用于 |
| --- | --- | --- |
| `pid` | 变化点序号 | 计件与去重候选键，需确认全局或范围内唯一性。 |
| `date` | 开始日期 | 按日统计新增件数；不是处置完成日期，格式和时区未明确。 |
| `factory/process` | 工厂、工序 | 范围核对；返回说明未列出 `dept`。 |
| `device` | 工作线 code；可为 `null` | 设备关联、设备明细下钻；空值属于非设备关联变化点。 |
| `type` | 人、机、法、料、环 | 映射人员、设备、方法、材料、环境；没有模具枚举。 |
| `changePointContent/potentialRisk` | 变化点内容、潜在风险 | 明细展示。 |
| `implMethod/implResult` | 管理方法、实施结果 | 明细展示，不能仅凭文本非空判断已关闭。 |
| `respPerson/reviewer/notes` | 责任者、审核者、备注 | 明细展示。 |

成功响应为 `success/code/message/data[]`，数组项仍为开放对象，上述字段来自接口描述，不是强类型属性定义。已明确返回banci、endDate（解除日期）、status（0进行中、1已关闭）；未明确状态历史、总数、分页或截断信息。

9月16日携带文档认证头的业务请求返回B0301；9月20日不带该头，仅传progress=成功返回2条。文档认证不能混用于业务查询。

## 参考图能否绘制

| 图中区域 | 支持程度 | 条件与缺口 |
| --- | --- | --- |
| 月内每日堆叠柱 | 五类有条件可做 | 对完整记录按 `date × type` 计数；需确认已关闭记录仍保留、无隐式截断，并能获得所选月份全部记录。 |
| 人员/设备/材料/方法/环境/模具六行日表 | 五类有条件可做，模具未支持 | 与柱图共用聚合结果；不能把设备类、备注关键词或未知类型强行归入模具。 |
| 各类别处置率 | 有条件可派生当前状态 | 同范围全部查询与 `progress=1` 查询，以唯一键匹配计算，需确认集合完整且状态一致。 |
| 历史月末处置率或每日关闭件数 | 当前契约不足 | 已声明解除日期endDate；历史时点状态及历史完整性仍未确认。 |

建议将“件数”定义为开始日期落在所选月份的新增变化点数：`N(日期,类别)=符合范围的唯一变化点数量`。多设备关联或重复行按业务唯一键计一次，不能按数组长度盲目计件。月内天数动态生成，2 月不画不存在的 30/31 日。确认完整覆盖的已发生日期无记录才显示 `0`；未来日期、缺失覆盖和请求失败显示空值或错误提示。`device=null` 仍应计入所属部门/工序，统计范围不能受地图可见设备白名单限制。

建议处置率明确命名“本月新增变化点截至当前关闭率”：先按开始日期筛选本月集合 `A`，再与同范围已关闭集合 `C` 按唯一键匹配，`某类关闭率=|A类∩C|/|A类|`。总体关闭率以总关闭数除以总件数，不平均各类百分比；分母为 0 显示 `—`。查询间状态变化会造成不一致，优先由后端一次返回总数、关闭数和快照时间。若业务要统计“本月处理了多少历史积压”，需关闭日期，不能使用上述公式替代。

图中六个百分比为 `50%、50%、100%、33%、100%、50%`，合计 `383%`，不可能是同一个饼图的类别占比。结合日表件数 `2、2、1、3、1、4`，可推测是各类关闭率（例如关闭 `1、1、1、1、1、2` 件），但这是对图片的推断，不能当作实际关闭数。建议右图改为各类别 0–100% 关闭率条形图，或已关闭/进行中的 100% 堆叠条。若必须保留饼图，应改为“各类变化点件数占比”，或仅展示总体“已关闭/进行中”两部分，不能把六类关闭率当作饼图权重。

## 放在哪个维度

| 页面 | 建议范围与位置 | 查询方式 |
| --- | --- | --- |
| 部门 | 当前部门全部工序汇总一张“变化点统计”卡，建议放在生产计划实绩趋势后；展开显示全月表格。 | 请求所属工序，合并后按确认的业务唯一键去重；任一工序失败时提示范围不完整。 |
| 工序 | 当前工序一张同构卡，与页面选择同步。 | `dept + process` 定位范围。 |
| 设备 | 可选增加关联变化点明细，不作为完整统计主入口。 | 查询设备所属科室/工序，再按 `device` 精确过滤；非设备关联记录无法归属单台。 |
| 全厂 | 后续可加“全厂变化点汇总”，显式标注范围和月份。 | 省略dept/process查询全部范围已实测成功；仍需确认唯一键、覆盖完整性和历史保留。 |

根据当前 `src/static/factory-map/selection.json` 与 Swagger，建议映射如下（尚待业务联调）：

| 页面工序 | `dept` | `process` |
| --- | --- | --- |
| `pretreatment1` | `1` | `前处理1` |
| `pretreatment2` | `1` | `前处理2` |
| `vulcanization1` | `2` | `加硫` |
| `posttreatment1` | `3` | `后处理` |
| `vulcanization2` | `4` | `加硫` |
| `posttreatment2` | `4` | `后处理` |

这里前处理1/2是两个查询范围，不能复用考勤将两者合成 `preprocessing` 的去重规则。跨科室的加硫、后处理也不能只按工序名称去重。按“全部+关闭”双查询方案，单工序需 2 次请求，部门需 2 或 4 次，当前六个工序的全厂范围需 12 次；这只是基于当前配置的估算，不是全厂完整范围已确认。

## 当前代码差异与接入前条件

- `src/api/schedule.ts` 的 `dept/process` 可选；地图一次查询全部范围，再按设备编码关联并筛选 `status=0`。
- `css3dMapLiveData.ts` 标签读取 `changePointContent` 等新字段，HTTP 或业务失败会记录全部变化点查询告警并返回空数组，设备其他实时数据仍保留；因此地图无标记不等于没有变化点。
- 地图只关联有 `device` 的记录，未知类别默认归为设备类；统计卡不能沿用这两个行为，否则会漏计非设备变化点并误分类。
- 接入前需确认：业务认证方式、模具枚举、唯一键范围、日期格式/时区、历史保留与分页、全部/关闭筛选、关闭率定义、全厂覆盖范围。
- 建议后端提供月份/日期范围过滤、明确状态与关闭时间、完整性和快照时间；数据较大时直接返回按日期/类别的总数、关闭数，并保留明细下钻。

当前卡片已按上方“当前实施状态”接入。后端唯一键、历史完整性、模具枚举与解除日期历史语义仍待确认，不将前端派生结果解释为历史月末状态。
