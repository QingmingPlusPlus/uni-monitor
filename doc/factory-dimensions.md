# 工厂可视化三维度说明

本项目是一个工厂可视化看板，用于在 2K 触摸大屏上集中呈现工厂运行状态。整体信息架构围绕三个维度展开：**部门**、**工序**、**设备**。

## 三个维度

### 1. 部门维度（Department）

- 路由：`pages/department/index?departmentId=department1`
- 描述：以部门为粒度展示当前科室覆盖工序的地图、稼动、人员出勤、趋势和计划实绩。
- 页面布局：顶部为 `Omni Monitor` + 当前部门告警跑马灯；主体为左右两栏，左侧约二分之一展示 `css-map`，右侧约二分之一为纵向组件栈。
- 右侧组件顺序：信息汇总、生产线稼动情况、人员出勤情况、人员明细及状态、出勤率推移表、入库计划实绩推移表。
- 数据范围：生产线稼动、人员出勤和人员明细仅展示当前部门相关数据；其中生产线稼动按当前部门下每个工序展示一行。
- 特殊规则：`departmentId === 'department1'`（制造1课）时不展示入库计划实绩推移表。
- 状态来源：`departmentId` query 是页面状态源。
- 长屏刷新：部门页按设备本地时间每日 06:20 软刷新一次显示数据；部门/工序看板不使用 `sessionStorage` 缓存整页接口结果，每次页面刷新或维度切换均重新读取。手动刷新按卡片粒度重新拉取被点击卡片的数据，不触发整页重载，不影响左侧 `css-map` 的部门/工序选择。

### 2. 工序维度（Process）

- 路由：`pages/process/index?processId=pretreatment1`
- 描述：以工序为粒度展示当前工序的地图、稼动、人员出勤、趋势和生产计划实绩。
- 页面布局：与部门维度一致，左侧约二分之一展示 `css-map`，右侧约二分之一为纵向组件栈。
- 右侧组件顺序：信息汇总、生产线稼动情况、人员出勤情况、人员明细及状态、出勤率推移表、入库计划实绩推移表、生产计划实绩推移表。
- 数据范围：生产线稼动、人员出勤和人员明细仅展示当前选择工序；生产线稼动只展示当前工序一行；入库计划实绩按当前工序所属部门聚合。
- 状态来源：`processId` query 是页面状态源。

### 3. 设备维度（Equipment）

- 路由：`pages/equipment/index?deviceId=1101&from=department`
- 描述：以单个设备为粒度展示停机、计划、损耗、原因、时间轴和周期信息。
- 页面布局：顶部为返回按钮 + `Omni Monitor` + 当前设备告警跑马灯；主体为全宽详情分析面板。
- 状态来源：`deviceId` query 是设备主键；`from` 用于返回部门或工序维度。

- 右侧 L 型设备可额外配置 `contentLayout: "right-l-shape"`。渲染器会从 `polygon` 提取横条高度和右侧竖条起点：名称与状态位于顶部横条，负荷率位于横条下半区左侧，人员与 5M 在其右侧分两行显示；右侧凸出竖条保持白色留白，不承载状态色、负荷率色或信息。当前 `CG涂装-2` 使用该布局，右侧竖条宽度为设备宽度的 20%；其横条与 `CG涂装-4` 之间保留 10 个局部单位的纵向间隙，竖条与 `CG涂装-4` 之间保留 5 个局部单位的横向间隙。
- 地图默认嵌入在部门/工序维度左侧，支持部门、工序选择和设备双击进入详情。
- 左侧地图提供展开按钮，点击后打开 80vw × 80vh 弹窗，弹窗内展示放大的 `css-map`。
- 地图弹窗内的部门选择、工序选择、清空工序和设备打开事件均不驱动页面路由切换，只用于弹窗内临时查看。
- 地图实时数据由 `src/components/css-map/css3dMapLiveData.ts` 聚合：设备工作状态、负荷率、人员配置和 5M 变化点均优先使用真实接口。
- H5 浏览器中可通过控制台全局方法 `window.mapMock(true)`/`window.mapMock(false)` 切换地图运行态数据源：`true` 使用前端 mock 数据渲染当前地图组件，`false` 恢复真实接口数据；开关写入 `sessionStorage` 并通知已挂载地图重新加载。
- H5 浏览器中可在手动平移、缩放到目标区域后调用 `window.mapCamera()`；函数会返回并在控制台打印当前渲染器、地图与视口尺寸、Three.js 相机位置、控制器 target、fov、aspect、near/far、相机距离，以及可复制给 `focusRect` 的 `focus.rect`。普通地图和展开地图同时存在时读取最后挂载实例，展开地图关闭后自动恢复普通地图。
- 地图数据加载期间显示居中的圆形 loading spinner；加载失败时显示错误提示。
- 加硫设备中 `HTI`、`STI375`、`STI450`、`STI450VY`、`STI450VX`、`STI450MVX` 设备节点省略机型，名称只显示设备编号（如 `STI375-1A01`、`HTI-2A01`、`STI450VY2A06` 分别显示为 `1A01`、`2A01`、`2A06`）；其他机型保持原名，设备编码不变。地图配置请求禁用浏览器缓存，展示层也会统一处理上述机型前缀，避免旧静态数据导致名称回退。
- 设备卡片外框、选择描边和点击区域始终覆盖设备原始占位；内部信息区根据设备原始宽高选择纵向或横向布局，并按名称、工况、负荷率、人员和 5M 标记数量估算内容宽度后进入稳定档位。纵向设备按名称、工况、人员、5M、负荷率顺序展示；横向设备使用紧凑横排。设备宽度超过内容档位时，信息区靠左显示且右侧保持白色留白。方向和宽度档位不随地图缩放变化，小尺寸设备仍允许名称省略，放大或聚焦后恢复完整名称。
- 人员配置继续使用班次扇形标记；5M 使用带正向“人/机/料/法/环”glyph 的填充菱形，并按人=紫、机=红、料=绿、法=近黑、环=黄固定配色。纵向最多使用三列两行六个槽位，横向最多使用五个单行槽位，超出容量以中性 `+N` 汇总；CSS3D 回退与 Sprite 使用相同形状、配色和布局规则。
- 地图右上图例在负荷率和工况分组下方显示完整 5M 颜色说明，色样复用设备卡片菱形；图例高度超过可用区域时在图例内部纵向滚动，并为右下角地图操作控件保留空间。
- Sprite 地图不做持续动画；平移、缩放、尺寸变化或数据变化时才渲染，并通过纹理缓存避免 80 个设备在连续交互中反复重建纹理。

## 推移表展示规则

- 推移类数据后端按日返回，前端按当前查询到的月周配置汇总成月、周和日。
- 出勤率推移和生产计划实绩推移的右侧小表列展示月列、接口周配置对应的周列、当前周工作日日列；即使日列对应日期尚未到达，也要展示列并以空值呈现；周六、周日因不出勤不展示。入库计划实绩推移使用下述专用周期规则。右侧小表不横向滚动。
- 紧凑表格的数值单元格在列宽不足时按实际内容自适应缩小字号，确保完整显示；行名和表头保持原有字号，展开弹窗仍按原规则支持横向滚动。
- 出勤率推移表的紧凑表格首列固定预留 `160px–176px`，确保“直接计划出勤人数”等完整行名不被裁切。
- 出勤率推移和生产计划实绩推移的展开弹窗展示月、全部周和当前月全部日；入库计划实绩推移的展开弹窗与紧凑视图使用相同周期列。列宽不足时允许横向滚动。
- 未到日期或接口返回 0 且不应视为有效数据时，chart 数据使用 `null` 跳过该点，避免折线骤降到 0。
- 出勤率推移中的利计出勤率固定为 91.0%；表格只在月列显示一个 `91.0%`，图表中展示一条 91.0% 红色目标线，并在线末端标注 `91%`。
- 出勤率推移表只展示并聚合到当前班次所属生产日；班次边界为 06:30、14:30、22:30，00:00-06:29 归属前一生产日晚班。月、周人数聚合显示为整数；其中间接在籍人数/直接计划出勤人数月/周平均剔除该指标为 0 的天，直接实际出勤人数月/周平均剔除直接实际出勤为 0 的天，直接实际出勤率月/周聚合也剔除这些天；百分比统一显示一位小数。
- 入库计划实绩推移表依次展示全月累计、截止设备本地当天（包含当天）累计、固定月内周段和当天所在周段的全部自然日日列；紧凑与展开视图规则一致。固定周段为 1–7、8–14、15–21、22–28、29–月末，月份没有第 29 日时不显示 `5W`，任何月份都不显示 `6W`。日列包含周六、周日且不跨月。
- 入库计划实绩推移折线图不展示全月和截止当天累计点；`0`、空值和非有限值不绘点，首尾无数据区间被裁剪，中间空类目保留并断线，空系列及其图例不显示。表格继续展示真实 `0`。
- 生产计划实绩推移表的表格保留月列，折线图不展示月列。
- 生产计划实绩推移表的日计划展示当日全部班次，计划周合计和月合计只累计到当前班次，排除当前生产日后续班次和未来生产日计划；凌晨晚班仍累计在前一生产日。

## 层级关系

```text
部门（Department）
  └── 工序（Process）—— 一个部门负责一个或多个工序
        └── 设备（Equipment）—— 一个工序包含若干设备
```

- **部门 → 工序**：由 `public/factory-map/selection.json` 维护部门与工序的聚合关系。
- **工序 → 设备**：由 `devices.json` 中设备的 `section` 字段关联。
- **设备详情**：以 `devices.json` 中的设备 `id` 作为 URL 主状态。
